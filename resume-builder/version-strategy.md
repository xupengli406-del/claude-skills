# 多版本差异化策略

同一份简历底稿，按 **岗位 × 公司** 二维矩阵裁剪/调权，输出不同投递版本。

---

## 一、岗位维度

| 岗位变体 | 重点能力关键词 | 应放大的项目 | 应弱化的项目 |
| --- | --- | --- | --- |
| **AIGC 产品经理（多模态）** | 多模态模型矩阵、内容生产管线、视觉效果把控、AIGC 商业化 | AI 漫剧 Agent、AIGC 多模态实践 | 招聘智能体（弱多模态） |
| **智能体 / Agent 产品经理** | Multi-agent 架构、工具调用、长程任务、MCP/工具生态 | AI 招聘智能体、AI 漫剧 Agent | 创业社区（弱 Agent） |
| **高级产品经理 / 产品负责人** | 跨职能协同、商业闭环、组织赋能、方法论沉淀 | 上海多云路（产品线整体负责）、AI 漫剧 Agent | 单点黑客松（弱组织维度） |
| **AI 应用 / 工具产品经理** | Vibe coding、AI coding 工具链、Prompt Engineering、效率提升 | 黑客松战绩、Cursor/Claude Code 重度使用 | 中兴（弱 AI 相关性） |
| **Agent Harness / Deployed PM** | 客户现场 Discovery、工作流拆解、Agent 任务定义、评测与反馈迭代 | Agent API、AI 招聘智能体 | 单纯赛事组织（弱客户部署） |
| **商业化 / 增长产品经理** | 双轨变现模型、行业洞察、GTM、数据指标体系 | AI 漫剧 Agent（商业化设计与行业洞察那条放第一） | 创业社区 |
| **AI 创业社区 / 初创营运营** | 项目发掘与判断、创业者服务、项目管理、导师嘉宾协同、活动运营、持续跟进 | 已确认的社区/黑客松组织、创业实践、创新项目研究与验证 | 与社区职责无关的模型/框架细节、重复产品功能清单 |

调权动作：

- **放大**：将最能证明目标能力的项目优先展示，依据已确认事实展开本人行动和结果；主项目通常 3–4 条，核心优势第 1 条概括相应能力。不能只调整顺序或堆岗位词。
- **弱化**：低相关项目缩至 1–2 条，或合并/移出核心项目区；任职时间线在工作经历中保留，不强制展开每个旧项目。
- **FDE 边界**：只有客户现场、工作流拆解、范围定义、原型/方案验证和现场反馈迭代证据齐全时，才写“FDE 型产品实践”；不要把产品经理角色改称 FDE，也不要补写未经确认的生产部署结果。

### 社区 / 初创营岗位的证据选择

以实际 JD/HC 为准，从已有材料逐项核对以下方向：

- **项目发现与判断**：项目接触、招募或筛选、行业研究、用户访谈、原型/商业验证；只写实际承担的环节。
- **活动和营期组织**：已确认的规模、选题策划、物料、招募、现场推进和活动后跟进。
- **导师与创新者服务**：导师/评委/嘉宾邀约、参与安排、沟通跟进或资源对接，各项分别需要依据。
- **创业者视角**：本人创业中的需求验证、取舍判断、技术与商业协作，可作为服务早期项目的相关经验。

这些方向用于选材和查漏，不能照抄为经历。只有活动组织证据时，不升级为已经运营过完整孵化营；只有跟进证据时，不改称投后管理。用户明确确认列出的职责后，可直接展开，具体补写边界见 `style-guide.md` 第 5 节。

## 二、公司维度

| 公司变体 | 招聘心智 | 写作语调 | 应突出的信号 |
| --- | --- | --- | --- |
| **大厂**（字节、阿里、百度、小红书…） | 看规范化交付 + 跨职能协同 + 规模化指标 + 学历 | 克制、数据导向、强调"沉淀方法论" | 跨部门协同、量化结果、行业报告深度、教育背景 |
| **创业公司**（A–B 轮、奇绩同期项目） | 看 Owner 心态 + 端到端能力 + 抗不确定性 | 锐利、动作导向、强调"独立完成" | 独立负责人头衔、奇绩二轮、组队博士+大厂高管、0→1 |
| **独角兽 / 准 IPO**（MiniMax、智谱、月之暗面…） | 看商业闭环 + 行业洞察 + 商业化设计 | 商业语境、强调"双轨变现/竞品图谱" | 商业化设计、双轨模型、火山引擎合作、横店产业园活动 |
| **出海 / 海外 PM** | 看英文交付 + 全球化视野 + 北美产品对标 | 简洁、Mercor / Cursor 等北美对标项放最前 | 对标 Mercor、对标硅谷、海外模型矩阵 Veo/Sora2/Pika |
| **垂直行业**（教育、影视、电商等） | 看行业 know-how + 落地案例 + 客户名单 | 务实、把行业项目放第一 | 横店产业园、火山引擎、有识咨询、客户合作 |

具体团队的职责优先于公司类别。例如大厂旗下创业社区应突出创新者服务和项目判断，不因“大厂”标签自动改写成规模增长或平台产品叙事。

调权动作：

- 改写**核心优势第 1 条**的措辞，把适配该公司的能力前置。
- 改写**意向岗位**字段，让 target 与公司岗位 JD 完全对齐。
- 改写**核心项目经历**首项的 bullet 排序，把适配该公司类型的能力维度放第一。

## 四、版本差异化输出模板

每生成一版定制简历时，必须在交付前给用户展示一段"调优摘要"：

```
本次定制版本：<岗位变体> × <公司类型>

变更摘要：
- 意向岗位：<原> → <新>
- 核心优势第 1 条侧重：<原维度> → <新维度>
- 核心项目：<项目 X> 对应 <关键职责>，补入 <已确认行动/结果>，移除 <重复或低相关内容>
- 工作经历：<职位 Y> bullet 数 N → M
- 底部技能行：补/删 <关键词>
- 页面检查：<实际 PDF 页数与留白情况>；仍未确认的关键事实：<如有>
```

让用户在读 PDF 之前就知道你做了哪些权重调整，节省他校对时间。

## 五、版本命名规范

PDF 文件名采用：

```
李旭鹏_<岗位简写>_简历_<公司简写或通用>.pdf
```

例：

- `李旭鹏_AIGC产品经理_简历_v2.pdf`（基础版）
- `李旭鹏_AIGC产品经理_简历_字节_v2.pdf`（字节定制）
- `李旭鹏_Agent产品经理_简历_MiniMax_v1.pdf`（MiniMax Agent 岗）

**版本号**只在底稿大改时递增（v2 → v3），同一底稿衍生的多家定制不增版本号。
