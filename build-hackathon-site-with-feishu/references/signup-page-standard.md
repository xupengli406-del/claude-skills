# 黑客松报名页标准

## 模板能力

`assets/site-template` 提供深色沉浸式活动网站、报名弹窗、服务端校验、本地数据库暂存和飞书同步的实现起点。新项目必须替换模板品牌、人员、照片、内容和链接。

## 字段确定方式

先从用户的新活动方案、报名问卷或目标飞书表格提取字段，再生成表单。不要从历史活动猜字段，也不要为了缩短页面擅自删除筛选信息。

至少确认：

- 联系信息。
- 组织、身份或角色。
- 赛道/方向。
- 个人或组队方式。
- 项目、作品或创意说明。
- 来源渠道。
- 隐私同意。

## 一步或分步

- 8 个以内短字段可使用单页表单。
- 字段多、含长文本或条件字段时使用三步表单。

推荐三步：

1. 基本信息。
2. 赛道、角色与组队。
3. 项目、作品或创意及隐私同意。

## 交互要求

- 显示当前步骤、总步骤和必填说明。
- 只校验当前步骤，错误聚焦到第一个无效字段。
- 步骤间保留输入，允许返回修改。
- 条件字段随答案显隐；隐藏字段不参与校验。
- 手机端单列、桌面端可双列，长文本独占整行。
- 提交前可显示关键信息摘要。
- 提交中禁止重复点击。
- 成功显示报名编号和真实同步状态。
- 失败区分“未保存”“已保存待同步”和“字段错误”。
- 弹窗打开后锁定背景滚动，Escape 可关闭，焦点保持在弹窗内。

## 服务端要求

- 服务端重复执行必填、邮件、URL、枚举和长度校验。
- 对自由文本处理表格公式注入风险。
- 使用活动 ID + 规范化邮箱或用户确认的稳定字段做幂等。
- 保存隐私同意版本与时间。
- 日志不输出完整个人信息。

## 飞书映射

以 `assets/registration-schema.csv` 为字段设计起点，根据新活动增删业务字段。每次修改必须同步更新：

1. 前端表单。
2. API 输入类型和校验。
3. 本地数据库字段/迁移。
4. 飞书表头和列映射。
5. 筛选视图。
6. 端到端测试。

## 验收用例

- 完整正常报名。
- 最少必填字段报名。
- 条件字段的不同路径。
- 重复报名更新。
- 非法邮件、URL、枚举和超长文本。
- 飞书短暂失败后的本地保留与重试。
- 手机端、键盘和读屏操作。
