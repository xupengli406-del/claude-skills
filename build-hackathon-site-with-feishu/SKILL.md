# 黑客松官网与飞书后台

只处理两件事：

1. 搭建黑客松活动公开网站和报名入口。
2. 将报名数据、详情文档和运营状态连接到飞书后台。

不要在本 Skill 中策划活动、制定赛事规则、编写主办执行手册或复用任何特定城市/场次的人员与内容。活动事实由用户提供的新场次资料决定；未知项使用占位符并列为待确认，不得从历史活动猜测。

## 一、启动流程

### 第一步：先复刻经典基线

1. 从 [assets/site-template](assets/site-template) 复制完整网站。
2. 读取并严格执行 [references/classic-spotlight-hero.md](references/classic-spotlight-hero.md)。
3. 保持占位活动信息，先复刻页面结构、双图地形聚光首屏、导航、标题层级、CTA、控制台和底部数据条。
4. 运行生产构建，确认经典基线可用。除非用户明确要求跳过，否则不得在基线构建前改成其他首屏方案。

### 第二步：再替换可变内容

1. 收集新活动的品牌、名称、主题、时间、城市、场地、赛道、日程、嘉宾、评委、奖项、合作方和已有飞书链接。
2. 确认官网报名字段、筛选需要的字段、隐私同意文本和数据访问范围。
3. 若项目含 `.openai/hosting.json`，读取并遵循 Sites building/hosting 工作流；保留现有架构。
4. 从 [assets/hackathon.config.example.json](assets/hackathon.config.example.json) 创建活动配置。
5. 替换人员、照片、奖项、日程和链接；模板占位符不得上线。
6. 用户需要时，再从聚光双图切换到视频、Canvas、Shader、图像序列或其他媒体模式。

## 二、官网范围

官网至少包含：

- 固定导航、品牌和报名 CTA。
- 全屏首屏及可替换动效背景。
- 活动介绍、赛道、日程。
- 嘉宾/领航者无限循环轮播。
- 评委、评分方式、奖项。
- 往届/现场回顾（没有授权素材时隐藏）。
- 更多信息：赛事细则、选手手册、获奖信息等飞书文档入口。
- 报名弹窗或独立报名页。
- favicon、Open Graph、移动端和无障碍适配。

页面结构、轮播、性能和动效规范见 [references/website-blueprint.md](references/website-blueprint.md)。经典首屏的完整 Prompt 与验收标准见 [references/classic-spotlight-hero.md](references/classic-spotlight-hero.md)；背景视频、Canvas、Shader 和图像序列等变体见 [references/motion-prompts.md](references/motion-prompts.md)。

## 三、报名体验

根据用户确认的字段决定一步或分步表单。字段较多时使用三步表单：基本信息、赛道/组队、项目/创意；不能为减少页面长度擅自删除筛选字段。

必须实现：

- 当前步骤校验、返回修改、移动端单列。
- 服务端再次校验、清洗、限长和枚举。
- 提交中、成功、失败和待同步状态。
- 打开弹窗自动聚焦、Escape 关闭、焦点管理。
- 隐私同意版本和提交时间。
- 重复报名的更新策略。

完整交互见 [references/signup-page-standard.md](references/signup-page-standard.md)，字段起点见 [assets/registration-schema.csv](assets/registration-schema.csv)。字段表是可配置模板，不代表任何特定赛事规则。

## 四、飞书管理后台

### 报名表

1. 创建或确认目标飞书电子表格。
2. 用 `sheets +info` 取得 Spreadsheet Token 和 Sheet ID。
3. 用 `sheets +read` 回读表头，建立前端字段、API 类型、本地数据库和飞书列的一一映射。
4. 表头至少保留系统列：报名时间、活动 ID、报名编号、来源、同意版本、同步状态和筛选状态。
5. 用户的业务字段按活动需要配置，不硬编码历史赛事字段。

### 网站双写

采用“站点数据库先保存、飞书随后同步”：

1. 表单提交到网站服务端。
2. 服务端验证后用稳定键 upsert 到站点数据库。
3. 生成不可逆报名编号。
4. 服务端使用飞书应用凭证获取 tenant token。
5. 新报名 append；重复报名更新原行。
6. 记录飞书行范围、同步时间和错误。
7. 飞书失败时保留本地记录并进入重试，不要求报名者重复提交。

凭证只放托管环境变量：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- `FEISHU_SPREADSHEET_TOKEN`
- `FEISHU_SHEET_ID`

具体 API、权限、重试、公式注入与隐私规范见 [references/feishu-backend.md](references/feishu-backend.md)。

### 飞书文档入口

- 赛事细则、选手手册、获奖公示等 CTA 使用用户提供的飞书文档 URL。
- 上线前检查目标文档的公开权限和访问范围。
- 新标签页打开并使用 `rel="noreferrer"`。
- 不在公开页面链接包含内部密码、密钥、个人电话或受限后台数据的文档。

## 五、网站数据管理方式

飞书中建议建立视图，而不是复制多份数据：

- 全部报名。
- 待同步/同步失败。
- 待筛选、入围、候补、未通过。
- 已联系、已确认、已撤回。
- 按赛道、队伍、来源的统计视图。

这只是网站后台的数据视图，不扩展到活动现场执行、预算、物料或主办 SOP。

## 六、上线验证

### 网站

- 构建成功，桌面和移动端布局正常。
- 导航、轮播、动效、弹窗、键盘和减少动态模式正常。
- favicon、标题、描述和 OG 正确。
- 所有活动内容来自新场次配置，没有模板人名、地点或历史链接。

### 报名与飞书

1. 提交一条带 `TEST-` 标记的虚构报名。
2. 回读飞书确认每列映射。
3. 用相同稳定键修改字段，确认更新同一行。
4. 验证飞书失败时本地数据仍保存且可重试。
5. 清理或标记测试记录。

### 交付

- 已部署官网 URL。
- 活动配置文件。
- 飞书报名表 URL 和字段映射。
- 飞书详情文档链接清单。
- 环境变量清单（不回显密钥）。
- 端到端测试结果和未确认项。

所有飞书写入必须用 `docs +fetch`、`sheets +read` 或文件夹重列回读验证。
