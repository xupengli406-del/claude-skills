# 连续讲解动画：默认制作规范

来自一条270.8秒、1080×1920、30fps数字人口播成片的已认可制作方式。复用信息组织、色彩与运动规则；不固定题目、片长、人物、六步结构或作者口音。

## 1. 先写观众正在理解什么

每个语义段只推进一个主要判断：它是什么 → 为什么这样做 → 怎样实现 → 有什么收益或局限 → 实际效果。工具名称紧跟具体作用，例如“Whisper取得实际词句时间，让字幕和小窗共用这份时间”，不能堆Remotion、API等名字充当专业感。

信息分三类：已知上下文保留在画面；当前新增内容随旁白出现；尚未解释的细节暂缓。画面可先出现对象轮廓或标题，不把后续结论全部预告。每次变换应增加事实、关系、对比或完成状态；只有漂浮、闪光和换颜色不算新增信息。

允许停留和相关内容并列，不要求画面每秒都有新元素。读图完成再推进，不能因“需要新信息”变成连续闪卡。若一个画面提前讲完，优先重排揭示时机或精简旁白；不加装饰填时长。

## 2. 默认视觉系统

| 角色 | 默认值 | 约束 |
| --- | --- | --- |
| 背景 / 纸面 | #EAE5DD / #F7F3ED | 全片同一暖灰基础，不逐镜换蓝绿紫 |
| 正文 / 次级文字 | #292B27 / #756D62 | 保持实际手机尺寸可读 |
| 强调 / 线 / 辅助底 | #985B43 / #BAAF9F / #DED6C9 | 一种强调色，线只表示真实关系 |
| 1080宽主标题 | 56–68px起步 | 每段一句，不能拥挤或悬空孤字 |
| 说明 / 注释 | 38–46 / 30–34px起步 | 少而有用，字幕通常44–50px |
| 圆角 | 18–24px | 统一组件，不层层套卡片 |
| 大移动 | 0.95–1.35秒起步 | smoothstep或同类缓入缓出，无弹跳过冲 |
| 小揭示 | 0.6–0.9秒起步 | 移动约12–24px配淡入，不能只做微弱透明度 |
| 阅读停留 | 简单结论约1.5–2.5秒起步 | 复杂图更长，结合真实语速和手机复核 |

分辨率变化按比例缩放。字体优先合法可用的中文黑体，包内不分发系统字体；更换为Noto Sans CJK等时检查授权、实际测量与换行。更换品牌色时整体替换token，不单独改某个镜头。

## 3. 六种可复用场景语法

1. **同一文档逐步展开。** 先出现文件或主问题，读到对应规则时加入一行，旧行保留；解释完成后整张文档收拢到侧边，给输入或结果腾位置。
2. **输入形成结果。** 先展示照片，再展示锁定声音，二者接入生成环节，返回实际数字人片段。每一步有可辨初态、转换、落点；不把箭头当所有场景的装饰。
3. **人物让出主画面。** 同一出镜窗口平滑缩小移动，资料在腾出的区域展开。保留嘴型正确的片段；照片只是照片，不能假装正在说话。
4. **修改前后对照。** 同一对象先保留原状态，再用明确的替换展示差异。例如三条轨道同时扣除同一段时间，直观说明为何必须同步。
5. **四层拆解再合成。** 四层沿正面或轻微倾斜展开，标签与内容都可读；发声层高亮而其他层保留上下文。合成后保持该时点的视频帧，不能突然换另一张静态姿势。
6. **收束到结果。** 已解释对象归入最终成片，回到自然人物结尾；画面在最后一句后留极短完整收尾，不拖尾讲空泛总结。

模板提供前四类的基础组件及四层展开/合拢示例；真实产品截图、比较数据和段落时码仍需本期准备。不能把占位图或示意波形说成真实素材/实测数据。

## 4. 连续转场的实现合同

- 优先保持同一个DOM/React对象，通过位置、尺度、容器尺寸变化衔接。只有语义确实切换时才换场。
- 进入下一场时，上一场持续可见到新内容接管；不要两个整页一起淡出露空底。可用遮罩交接，但不得让两组文字叠读。
- 标题单独交接：旧标题退出后新标题进入，避免遮罩中半句旧字拼半句新字。
- 同一面板替换文字时，先让旧标签离开，再显示新内容；保留面板或主要对象的位置线索。
- 圈注使用原素材坐标，通过实际裁切缩放矩阵映射到成片。不能估计屏幕坐标圈嘴却圈到下巴。优先局部放大/准确高亮；没必要不圈。
- 大头像放大覆盖浅底时，字幕颜色根据**字幕位置实际覆盖的背景**切换，不能凭总体动画进度猜。先保证对比，再考虑颜色过渡。
- 不加常驻“制作流程示意”“数字人口播教程”页眉、装饰进度线或流水号。片中已有的必要服务水印/披露不能移除；发布时按事实选择平台AI内容声明。

## 5. 同一时钟与嘴型映射

实际音频是时间基准。用Whisper或可用对齐器校正词句时码；口播文本不能按字数均分。字幕在语义边界换行，不将“画面合成”等短语拆成不自然的尾字。

记录每个保留区间：源音频入点/出点、成片入点、速度，以及对应的数字人源文件和源入点。若只生成出镜句子，还需记录拼接到HeyGen输入中的位置。成片时间换算必须应用到声音、字幕、嘴型和动效。高光前置会额外引入源时间回跳，不能仅把人物视频整体平移。

模板的`avatarSegments`支持`from/to/sourceFrom/rate`，每个区间使用局部Sequence控制视频，静音视频重复音轨；只有覆盖区间才显示出镜，不默认循环嘴型。字幕与动画事件用绝对成片秒数。旁白改写后重新对齐；只改画面不重做已认可声音。

## 6. 音效与声音

短句、重音、停顿和自然语气在生成前解决；不能靠统一倍速挽救有气无力或错读。取得认可声音后保持配置。混音以清楚人声为准，不把响度达标当自然度达标。

图标沿用一套，如包内Lucide ISC图标；音效需有可核对许可和来源。Pixabay等允许用于作品不一定允许把原始音效作为可分发素材库，分享Skill时默认不打包这些原始音效。模板仅附本包程序生成的轻提示音脚本，不冒称商业音效库。实际项目若使用media-use，保留来源和许可记录，核对可用范围。

## 7. 留存不是越快越好

开头短高光提供看得见的结果，正文继续解释其原因。每段尽早兑现一个小问题，删掉重复介绍和“接下来你能看到…”的空话；保留理解所需的停顿。收藏价值来自可复用判断/做法，而非口头索要收藏。

首次发布前可检查：前2秒是否有具体观看理由；每段是否持续推进；解释是否兑现封面承诺；结尾是否自然。发布后有数据再分别看2秒流失、平均观看、分段流失、完播、收藏/分享，并结合片长和流量来源比较。没有平台数据不能说“完播率已提高”，也不为完播率盲目删除必要内容。

## 8. 验收与费用范围

先完成一个覆盖人物→资料、小窗、信息揭示和跨场衔接的短段。用户认可后扩展；不要每次重新问同样许可。检验实际导出全片：逐接缝前中后、完整解码、缺轨/字幕、音画同步、手机可读性。1×完整观看/试听能做则做，不能做就明确标注；静帧、ASR、波形和技术脚本都不能代替。

默认保守并发，包含OffthreadVideo时从1开始；机器通过实际视频渲染再增加。长片可分段续渲，但缓存签名必须含源代码、数据和引用素材。渲染源静帧正确不证明导出视频没有解码错帧。

分享模板已验证的范围与真实外部服务生成分开记。模板运行成功不保证任意账号都有HeyGen权限、相同声音表现或已完成肖像核验。
