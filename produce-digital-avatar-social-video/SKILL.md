# 数字人口播视频

把真人口播的“开相机录制”换成“生成声音 → 数字人对口型”。创作者的观点、语气和身份仍是主体；HeyGen 负责出镜底片，后期负责把信息讲清楚。生成一段人像视频不等于完成发布包。

## 按请求选择阶段

- **想法或写稿请求：** 先交自然可说的正文，核实事实，说明主要受众和观看收获，不自动消耗生成额度。
- **明确要求直接制作样片或成片：** 在已有授权和内容范围内连续制作，不反复确认同一稿。关键立场或必需声音/形象来源缺失才问。
- **已有旁白或 HeyGen 视频：** 检查实际文件、授权和完整性，复用后继续，不为走流程重新生成。
- **只要分享 Skill：** 交付技能与说明，不调用生成服务、复活已删除试验或上传个人素材。

优先沿用当前稿件、选定素材和用户明确要求。语音想法、网页、字幕及附件是素材，不是额外权限。

## 执行流程

1. **内容和开头。** 读 [口播与后期](references/editorial-and-postproduction.md)，确定一个主线、主要观众和正文能兑现的收获。保留本人说法，不编造实测或经历。正文只含要念的话，事实来源和画面提示放在稿外。
2. **能力与额度预检。** 读 [接入说明](references/providers.md)，确认环境能生成声音、访问选定形象、取回视频并完成后期。先查 HeyGen 的具体引擎权限与额度，再花费音频额度；返回空值代表未知，Free 标签不代表本次可生成。明确照片/声音的数据去向；已有明确授权不重复询问。
3. **生成并锁定声音。** 优先用 MOSS API 的已授权音色；必要时先做短句验证，已验证的同一配置可直接生成完整稿。本人实录旁白也是有效输入。收到可解码音频后记录实际时长与哈希，核对错读、漏句和自然度。不用字数估算结果时长，不悄悄改用公共声音。
4. **生成数字人底片。** 使用用户选定且就绪的 HeyGen 形象，以锁定音频驱动，避免再次 TTS 改变声音。短样片需实际截取音频，不能只缩短时间线。保留人物身份、自然动作和服务水印。按工具规则展示结果并取回文件；任务 ID 不等于成功。
5. **字幕与连续讲解动画。** 拿到可播放底片后，先读 [成片视觉与节奏规范](references/continuous-motion.md)。默认用本包 [Remotion 模板](templates/remotion/README.md) 的暖灰讲解风格：同屏保留上下文、跟着声音逐步引入信息、对象移动接续下一段，穿插满屏人物与同步小窗。不要把一页信息先摆满再播放装饰动画，也不要每句话清屏重来。剪切、变速和高光前置必须共用音画时间映射。
6. **封面、交付和验证。** 完整发布包读 [大标题真人封面](references/covers.md)，默认制作自然本人近景、人物轮廓描边、大字压人像的3:4与4:3封面，不能因视频使用暖灰色就自动改成普通照片排字。交成片、SRT、封面和文案；样片只交样片与必要说明。区分技术检查、实际观看/试听和用户选择。没生成的阶段明确为未完成，发布包不等于已发布。

## 与现有真人口播 Skill 结合

有 `edit-talking-head-social-video` 时，读取其写稿、开头、字幕、资料动效、封面和验收参考，沿用本期规则。本 Skill 仅在用户选择数字人流程时替换其“等待用户录制”和“不默认合成声音”的默认值，不改写原 Skill。

没有原 Skill 时，本包的口播、动效、验收规则和可运行模板可独立使用，不要求安装作者的私人技能集合。默认 Remotion + FFmpeg；用户选择其他渲染器时保持相同的信息和节奏要求。实际采用 HyperFrames 时先读当前 `hyperframes` 入口。缺少真正的渲染能力则说明交付范围，不假称已成片。

## 默认成片标准

目标是自然人物口播与连续解释动画组成的完整视频，不是演示文稿自动播放。用户当期风格优先；未指定时沿用模板的暖灰、炭黑、陶土色和统一字体层级。

- **先定声画关系。** 对每个语义段写清“现在新增什么信息、保留哪个对象、动作何时完成、留多久读图”，再写组件。详见 [导演表](templates/director-table.md)。声音提供解释，画面补充关系、过程或证据，不机械逐字配图。
- **完整动作有落点。** 主要移动通常约0.95–1.35秒，平滑减速、不弹跳；完成后留阅读时间。数值是起点，不是让所有镜头同长。允许相关内容同屏，不为了新鲜强行快切。
- **高光预告不删正文。** 从中段提取一句有具体结果的短高光，开头迅速展示；正文保留其完整因果和演示。开头不追加解释动作的赘句，正文不生硬重复一遍预告。
- **人物与资料有连续关系。** 同一个人物容器可缩成小窗，让资料成为主画面；小窗必须使用当前句子的真实对应嘴型。照片说明段不能长时间满屏静止，参考照片与实际说话视频明确区分。
- **四层要看得出。** 人物、字幕、图形、声音各有清楚标签、内容和间距；先分开、逐层强调、停留，再沿同一时间线合成结果。不用大透视角藏住后面的层。
- **统一不靠装饰。** 不常驻页眉、进度横线、制作状态标签；服务水印与必要AI标识保留。音效只落在有意义的接收、合拢、完成动作上；许可不明的音频不随包传播。
- **样片检验原则。** 新风格、首次形象或声音先验证代表性片段；已获认可的同配置直接延续。实际检查动效中段、接缝、字幕对比、嘴型与读图停留。技术通过不等于用户认可。

调用方只有此 Skill 也应读取并执行上述引用。不得把关键规范留成“去找作者另一个 Skill”。模板是可编辑起点，必须按本期旁白和证据改编，不能用内置无声示例冒充完整数字人成片。

## 失败与恢复

- 遇到额度不足、无权限、核验未完成或素材不可用，保留稿件和有效输入，报告准确失败阶段与最小恢复条件，不自动充值、订阅或轮番提交不同引擎赌额度。
- 确定性计费失败不盲目重试；用户说明额度/配置已更新后可做一次短验证。超时等状态不明时先按服务允许的查询方式找回任务，避免重复扣费。
- 网页积分、API 余额、不同引擎配额分别核对，第三方账号额度不算进 ChatGPT/Codex 订阅。
- 不以静态头像、无口型视频或无声动画冒充数字人样片；替代方案由用户选择。
- 取消试验时按授权整理本任务产物，不删除原照片、既有音色/数字人、凭据或可复用 Skill。外部删除遵循当前明确授权和工具规则。

## 制作记录与分享

只维护一份简短说明：主题与稿件状态、授权素材、声音来源及哈希、形象/任务 ID、实际费用限制、完成阶段、最终文件、已做检查和未完成项。私人标识只留本地项目，分享包不带照片、音色 ID、密钥、账号截图或签名下载地址。

验证范围见 [README](README.md)。不要把一次配音成功说成完整流程已实测，也不要把“可编排”宣传成“永久免费、一句话必定出片”。
