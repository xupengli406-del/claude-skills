# 无露脸录屏解说视频

把原始录屏制作成有叙事、有证据、有解说的社媒视频。默认保留原片，交付精简成片、口播稿和字幕文件。

## 工作流

### 1. 确认输入与交付

获取原视频路径，并根据上下文确定：

- 发布平台与横竖屏比例；
- 核心受众、一个主要结论和一个行动引导；
- 是否需要真人声音、AI 声音、背景音乐或品牌片头；
- 必须展示的画面证据。

信息足够时直接制作，不重复询问。绝不覆盖原视频。

### 2. 检查素材

使用 `scripts/inspect-recording.ps1` 或等价命令读取时长、分辨率、帧率、音轨并生成联系表。必须实际查看联系表和关键帧。

标记：

- 保留：结果、功能、关键交互、真实证据；
- 加速：输入、滚动、等待但仍需理解的过程；
- 删除：报错、重复、误操作、加载空白、无意义停顿；
- 脱敏：手机号、邮箱、姓名、Token、表格中的私人信息。

### 3. 设计视频叙事

按以下结构组织画面：

1. 结果或视觉钩子；
2. 产品解决什么问题；
3. 核心操作流程；
4. 后台回写或结果证据；
5. 信息完整度或扩展能力；
6. 总结与行动引导。

普通社媒演示优先控制在 30–60 秒。过程片段通常使用 2–5 倍速；提交成功、数据回写和关键结果保持 0.9–1.3 倍速。

### 4. 写口播并生成配音

口播必须跟随画面，不写画面无法证明的功能或效果。每句话对应一个视觉阶段，中文解说通常按每秒 4–5 个汉字估算。

默认使用自然中文神经语音；在 Windows 可用 `edge-tts`。使用 `scripts/new-narration.ps1` 同时生成音频和 SRT。若环境没有 `edge-tts`，使用已安装的系统中文语音或请用户提供声音。

### 5. 制作成片

将剪辑计划保存为 JSON，格式见 `references/segment-plan.example.json`。每段必须包含：

- `start`：原片开始秒数；
- `end`：原片结束秒数；
- `speed`：播放速度。

使用 `scripts/render-video.ps1` 合并片段、放大、锐化、烧录字幕、标准化旁白响度并输出 H.264/AAC MP4。

分辨率默认：

- 横屏产品录屏：1920×1080；
- 竖屏内容：1080×1920；
- 需要完整保留界面时使用 `fit`，允许裁切时才使用 `fill`。

放大只能改善发布规格和文字边缘，不得声称恢复了原素材不存在的细节。

### 6. 质量验收

交付前必须完成：

- 用 `ffprobe` 验证时长、分辨率、帧率和音轨；
- 完整解码测试，确保无损坏；
- 再生成一张成片联系表，检查画面顺序；
- 抽查字幕首段、中段、末段，确认无遮挡和无乱码；
- 检查旁白与画面是否对应；
- 删除报错提示、空白加载和私人信息；
- 检查响度，旁白建议约 -16 LUFS，真峰值不高于 -1.5 dBTP；
- 保持原视频不变。

### 7. 整理交付

最终目录默认只保留：

1. `主题_1080P配音字幕成片.mp4`
2. `主题_中文口播稿.txt`
3. `主题_中文字幕.srt`

删除联系表、抽帧、旧版本、临时音频、滤镜脚本和测试输出。使用中文名称让非技术用户能直接判断用途。

公开发布属于外部操作；只有用户明确要求并在发布前确认后才能执行。
