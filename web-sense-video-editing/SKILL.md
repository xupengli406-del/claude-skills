# 网感剪辑

维护一个可增长、可追溯、能实际执行的方法库，并用它完成用户的视频剪辑。首批来源为凌川屿 Vol.12 的约 21 秒拆解片段。

用户已明确认可首批视频里的全部做法：全部收录，允许字幕、画面和声音组合强调。每条视频的使用密度根据用户要求、参考片和实际观看结果决定，不套用固定的“每几秒只能动一次”限制，也不把方法库缩成少数温和效果。

## 根据请求进入工作

- **收录参考视频、扩充方法库：**读[收录规则](references/collection.md)，取得真实内容和时间线，把每项明确标注及可见做法逐项入库。复用既有 ID，新机制增加 ID；保留全部来源与变体。
- **剪辑已有视频、增强网感、按参考处理：**直接进入下方剪辑流程。利用实际原声和现有工程，不要求先重走写稿审批。
- **只问方法或要求某种效果：**读对应条目并完成所需解释或局部处理，不默认重剪整片。

没有用户视频时可完成方法收录与方案；执行剪辑确实缺少输入时明确请求缺失素材，不以参考视频冒充用户成片。

已有视频且没有额外要求时，沿用其画幅、语言、原声和已选风格；新工程按参考决定网感强度，局部返修沿用原工程。仅增强网感默认交付视频、可编辑工程和简短使用记录；封面、重写稿件、合成新声音及发布属于另外的任务范围。不要为已有视频重新进行一轮创作需求访谈。

## 查找方法

先读[方法索引](references/index.md)，按表达任务读取详细库：

- [文字与语义标注](references/text.md)：字体、阴影、描边、五种文字动画、字号层级、图标、斜向文字、细节旁注与标签字幕。
- [画面与空间处理](references/picture.md)：缩放、同步复制、动态抠像、人物遮挡、烟花、素材、圆形与矩形蒙版、入屏、收束、硬切、定格、调色和局部明暗。
- [声音搭配](references/sound.md)：首批七种短音与一个音乐片段，以及各自的落点和使用方式。
- [组合配方](references/recipes.md)：原片中的八组联动；组合使用时读，不能只拿一个效果替代整组。
- [首批来源与覆盖对照](references/cases/lc-vol12/case.md)：核对原作者名称、时间和截图时读。视频与截图是分析证据，实际输出换成用户素材。

详细条目中的参数为实现建议；原作者未展示的字号、缩放比例、曲线和音量不能宣称是其原始参数。名称不清、标题截断或预设中间运动未确认的项目仍保留，注明已知功能与待核信息。

## 实际剪辑流程

完整新剪辑或多层组合先读[可执行流程与状态检查](references/execution.md)；简单局部修改可复用原工程中的对应记录。

1. **接入素材。**检查原视频、声音、字幕、现有工程、用户选定版本和参考，取得实际时长、画幅、帧率和音轨信息。先确认本次编辑器/渲染工具、字幕对齐、动态抠像、声音素材及字体路径，缺少能力时落实可用路径或明确具体缺口。确定源片到成片的时间映射；没有必要不改原声、不重写观点。
2. **建立剪辑落点。**按真实说话标出主题、情绪词、程度词、动作、产品细节、转折与表情包袱。为每处选择方法 ID 或组合配方；参考风格较密集时保留相应的联动强度。普通讲述段也属于节奏的一部分。
3. **记录并实现。**完整新剪辑或多层组合保存 `edit-plan.json`，记录源片区间、成片时间、原声锚点、方法 ID、作用对象、文字、声音、素材依赖及当前参数；先运行 `scripts/validate_edit_plan.py <计划路径> --stage plan`。简单返修只更新原工程相关记录。随后落实到实际时间线或可渲染工程，按实际进展更新状态；用户要求剪片时不能止于策略表。
4. **按工具执行。**读[实现与工具衔接](references/implementation.md)。用户指定编辑器时使用该工具；延续现有工程优先保留其工具。制作 HyperFrames 视频时读取当前可用的 `hyperframes` 入口；真人口播的完整后期可结合 `edit-talking-head-social-video`，本 Skill 负责其网感处理部分。实际能力以本次工具和素材为准。
5. **查看真实导出。**完成所选组合后运行实现检查，再导出并以正常速度检查动作、文字和声音的配合，检查关键边界前后，修复具体问题后更新当前导出。截图只能确认布局，不能代替过渡与声音验收；无法完成的检查如实说明，不标成已通过。
6. **完成交付。**交付可预览成片、必要的可编辑源文件及实际使用的技法记录。按用户项目的整理要求处理已确认废弃的试片与重复检查素材，保留当前工程及依赖。

日常处理在已授权范围内连续完成。只有缺少必需输入、实质改变用户观点或超出任务范围时才需要澄清，不把样片审批设成所有任务的固定门槛。

## 关键实现约束

- “文字放大预设”“画面关键帧放大”“定格帧放大”是不同处理，按目标对象实现。
- 同一句字幕内放大重点词时，按 [V24 的自然衔接规则](references/text.md#V24)处理：整句先以普通字号和自然间距显示，发声到重点词时再放大，并让邻字同步平滑让位；检查强调发生前的状态，不能只看放大完成态。
- 人物遮挡文字需要同步的动态前景和正确层级，复制层保留一份声音；不要用一张静态人像冒充连续人物抠像。
- 蒙版、素材和文字不应遮住正在展示的部位；画面缩放以本次焦点为中心，原片与抠像层保持相同变换。
- 卡片预览中的人物不是原片插入的反应图；素材卡片停留时长不是声音的实际播放时长。
- 找不到同名预设时可实现经核对的通用近似，保留实际做法记录；不能悄悄声称实现了未经核对的原版预设。
- 用户喜欢的强烈、密集或幽默风格优先。修正具体的遮挡、错位、不可读或听不清问题，不用笼统的“克制”取消已要求的效果。

## 验收与扩充

验收依据为：效果确实可见，落在相应词语或动作上，文字可读，遮挡和蒙版连续，原声可听，结尾与转场没有空帧或突兀跳变。输出明确区分“已实现”“已导出”“实际观看/试听”和“用户已选定”。

扩充库后执行本 Skill 的 `scripts/check_library.py`；创建或修改入口后运行当前 skill-creator 的校验工具。所有 scripts 路径相对本 Skill 安装目录，从用户工程运行时使用实际脚本路径，不假设用户项目也有此 scripts 目录。此检查覆盖方法与来源的对应关系、证据文件和本地引用，不能代替使用技法后的成片验收。

库中记录的是“可用技巧”；本次已选、已实现、已导出和已观看/试听分别记录。每次根据真实使用问题做有证据的窄改进，不把一个失败扩张成适用于所有视频的限制。
