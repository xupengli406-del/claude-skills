# 让观众能跟着完成

## 写稿时

先确定观众要完成的真实任务，以及实际需要的账号、文件、权限和工具；只说明本任务使用处必需的条件，不堆名词。用一条完整演示串起输入→操作→结果→验收。每个步骤写出要做什么、在哪个真实入口做、带什么输入、应看到什么，以及出现具体差异时如何判断；未知入口先核实，不凭印象写UI。

交可直接念的正文。录屏点、待录输入、需要保护的隐私、真实示例和预期结果放稿外。拟议演示标明待验证，不能把未来画面写成已经完成。前三秒从实际支持的观看理由起，必要条件紧接交代，不承诺任何任务都能免账号、免费或无需网络。

## 收到真实素材时

以原片确认入口、参数、鼠标、输入和反馈。文字稿不覆盖真实改口；操作顺序按因果保留。等待/加载可按语义缩短，保持前后状态清楚；错误、重试若影响复现须交代，不能只拼一个假顺利流程。屏幕录制不能用自制界面冒充；遮隐私时保住必要上下文与核验信息。

每段在已有时间线记录源区间、成片区间、声源/变速、当前观看对象、步骤、材料出处及显示点、结果检查。本人和屏幕从同一母时钟求位置；局部停帧/速度变化显式映射，不让嘴型、鼠标与字幕各走一套。

## 验收时

从观众输入重新读一遍：所需文件/权限已说明，关键操作看得清，输入能复制，反馈与结果确实来自原片，验收能判断成败。再看实际导出的开头、全部关键点击/输入/结果与字幕状态；既有教程可作历史形式参考，不能充当本次新包端到端测试。
