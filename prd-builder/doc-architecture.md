# 文档骨架（9 大章节固定）

`prd-builder` 输出的 PRD 永远遵循下面这个骨架。**章节顺序、编号样式、必备子章节都是品牌资产**，不要改。

---

## 一、版本信息

三列 `<grid cols="3">`，每列一个 `<callout>`：

| 列 | 图标 | 内容 |
| --- | --- | --- |
| 1 | `alarm_clock` | 版本号 |
| 2 | `calendar` | 创建日期 |
| 3 | `cop` | 审核人 |

**规则**：

- 版本号格式 `v{大版本}.{小版本}`，例如 `v1.0` / `v1.3`。
- 大版本：架构级重构（如：单轨计费 → 双轨计费）。
- 小版本：模块新增、UI 重构、规则调整。

新增/变更的内容用 `<text color="red">` 包红，参见 [changelog-convention.md](changelog-convention.md)。

## 四、需求背景

固定三个二级标题（即使内容暂时为空，也要保留标题占位）：

- **用户调研** — 用 `<mention-doc token="…" type="docx">…</mention-doc>` 引用飞书调研文档

## 五、需求范围

### 模块总览

`<lark-table cols="4" header-row="true">`，四列：**编号 | 模块名称 | 能力描述 | Demo 实现状态**。

模块顺序按**用户使用路径**：

```
登录 → 工作区 → 创作（图片/视频）→ 整理文件 → 计费
```

具体到当前产品：

| 编号 | 模块名称 | 一句话能力 |
| --- | --- | --- |
| 1 | 账户系统 | 注册/登录/注销/个人信息 |
| 2 | 工作区框架 | 多标签页 + 分屏的容器 |
| 3 | AI 图片生成 | 对话式生成分镜图 |
| 4 | AI 视频生成 | 对话式生成视频片段 |
| 5 | 文件管理系统 | 资源整理与命名 |
| 6 | 计费系统 | 订阅 + 按量双轨 |

Demo 实现状态枚举：`已完成` / `Mock` / `UI 原型` / `模拟态` / `待实现`。

### 说明

放本次 PRD 的**作用域声明**：

- 本期不做：列出明确不在本版本的能力（防止评审跑题）。
- 本期做：再次强调本版本要交付的核心能力。

## 章节生成顺序的最佳实践

虽然最终读者按 1 → 9 读，但**写作顺序**应该是：

```
五（模块总览）→ 六（详细）→ 六附（架构流程）→ 一/二/三/四（背景说明）→ 七/八/九（非功能/埋点/规划）→ 附录
```

先把"做什么"写清，再补"为什么 / 怎么验收"。强行从一开始顺写，往往背景越写越虚。
