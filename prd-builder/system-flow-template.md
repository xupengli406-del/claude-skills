# 系统架构与 ASCII 流程图规范

「六（附）」与「六（附二）」两章是把 PRD 拉进"研发可执行"档次的关键。本规范给出可直接套用的范式。

> **不要用 mermaid**。飞书、GitHub、本地 markdown 三端渲染兼容性差。ASCII 是唯一稳定的选择。

---

## 一、节点说明（每个 PRD 必备）

固定 `<lark-table cols="3" header-row="true" column-widths="244,244,244">`，三列：

| 节点 | 类型 | 职责 |
| --- | --- | --- |
| 短剧前端 | React SPA | 用户直接交互的界面 |
| 短剧后端 | FastAPI 服务 | 业务逻辑编排 + 存储配额管理 + 调用中台/MaaS API |
| CloudsWay MaaS | AI 模型调用网关 | 实际执行 AI 推理（Seedream/Seedance），自行将 API 计量数据推送给中台 |
| 中台 | 公司级中台 | 用户管理 + Token 余额 + 计费 + 账单 + Stripe 对接 |
| Stripe | 支付网关 | 由中台直接对接，订阅自动扣费 + Token 充值支付 |

新产品要替换节点名，但**列结构 / 行数 4–6 行**保持。

## 二、ASCII 流程图标准箭头集

可复用的字符（确保等宽字体下对齐）：

```
框线：┌ ┐ └ ┘ │ ─ ┬ ┴ ├ ┤ ┼
箭头：→ ◀ ▼ ▲ ▶ ◁
合流：└─┬─┘   ├──┐
分支：┌─┴─┐
```

**不要用** `->` `<-` `==>` 这种 ASCII 模拟箭头。要用真正的 Unicode 箭头字符，飞书等宽字体能正确对齐。

## 四、流程编号约定

| 编号 | 用途 | 必含路径 |
| --- | --- | --- |
| 流程 1 | 注册/登录流 | OAuth → 中台 → 前端 token 落地 |
| 流程 2 | AI 生成调用流 | 前端 → 后端预扣 → MaaS → 成功实扣 / 失败释放 |
| 流程 3 | 订阅 + 充值流（如双轨） | Stripe → 中台 → 前端余额刷新 |
| 流程 4 | 余额详情与账单 | 中台账单 API → 前端展示 |

如果产品形态没有计费，删掉 3、4，但 1、2 必有。

## 五、关键设计点（每条流程必写）

紧跟流程图后面，用红字 bullet 列 **3–5 条**关键设计选择，回答"为什么这么设计而不是别的"。

例：

- 预扣/实扣/释放三步走：调中台预扣 → MaaS 生成 → 成功调中台确认扣费 / 失败调中台释放冻结
- 三道门槛：订阅状态 → Token 余额 → 存储配额
- 生成失败不扣费：释放冻结金额，行业惯例
- MaaS 返回的临时 URL 有效期仅 24 小时，必须在生成成功后立即转存到 TOS 永久 Bucket

## 六、各方职责矩阵（章节末必备）

`<lark-table cols="N+1" header-row="true">`：第 1 列「职责」；第 2..N+1 列每个节点一列；单元格写 `✓` / `承担` / `不涉及` / `仅记录`。

例：

| 职责 | 短剧前端 | 短剧后端 | MaaS | 中台 |
| --- | --- | --- | --- | --- |
| 用户注册 | 提交表单 | 透传 | — | 写入用户表 |
| Token 余额 | 显示 | 查询 | — | 持久化 + 预扣/释放 |
| AI 推理 | — | 调用 | 执行 | — |
| 计量推送 | — | — | 推送计量 | 接收并对账 |
| 支付 | 跳 Stripe | — | — | 对接 Stripe |

让所有相关方一眼看到自己负责什么、不负责什么。

## 七、用户旅程图（六附二）的 ASCII 范式

旅程图用横向时间轴，每个节点是一个**触点**，旁边标 **决策点** 或 **可选路径**。

```plaintext
注册      首次创作      余额警告       充值/订阅     长期活跃
  │           │             │             │             │
  ▼           ▼             ▼             ▼             ▼
  ●───────────●─────────────●─────────────●─────────────●
  │           │             │             │             │
  │           │             │       ┌─────┴─────┐       │
  │           │             │       │           │       │
  │           │             │    充值          订阅      │
  │           │             │       │           │       │
  │           │             │       └─────┬─────┘       │
  │           │             │             │             │
  │     [模型选择]    [余额提示弹窗]   [支付弹窗]      [续订]
  │     [生成提交]    [是否继续]
  │
[OAuth]
[免费配额触达]
```

每条旅程之后写 **关键转化点 / 流失点**：

```
关键转化点：首次创作完成 → 看到结果即转化
关键流失点：余额警告时若无明显引导 → 70% 用户离站
```

## 八、ASCII 排版自检

- 用等宽字体（系统会自动等宽，但写的时候用 VS Code 等等宽编辑器看）。
- 框线右边界对齐，每行长度一致；不一致用空格补齐。
- 中文字符宽度 = 2 ASCII 字符宽度，但飞书代码块按 ASCII 计宽 → 中文段后右框线会左移，需用更多空格补齐。提交前在飞书预览看一次。
- 用 Unicode 圈号 ① ② ③ ④ ⑤ ⑥ ⑦ ⑧ ⑨ ⑩ 标步骤，超过 10 步用 ⑪ ⑫ … 或拆流程。
